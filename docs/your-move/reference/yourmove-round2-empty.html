Your Move — Round 2: Empty States

Three ways the product can be empty, and they are not the same state. Each gets its own honest rendering. Palette: Dusk. Annotations below each mock carry the truthfulness rationale.

A Fresh empty — no work exists at all

First run, or everything archived. The lamp is unlit because there is nothing to need you — and the screen says plainly that the log is empty, not that "you're all caught up."

  • A1Empty log, stated. "The log is empty" is a fact about the event log, not a vibe. It rules out the failure mode where the UI shows a friendly empty state while events failed to load.
  • A2The CTA teaches the write path. The only button starts the describe → draft → approve flow — reinforcing that creation is owner-approved, never ambient.
  • A3Unlit lamp, dimmed. The lamp reads "off," not "broken." No glow anywhere on screen — one signal color, one meaning, even at zero.

  • B1"Nothing needs your move," not "all caught up." The rail describes the queue's state, not the manager's virtue. Timestamped to the revision — if the projection goes stale, this line is what goes stale with it.
  • B2Calm list, honest rows. "No signal since r429" instead of "idle." "Verified r428" instead of a bare checkmark. Every row still exposes its source revision, even when nothing is wrong.
  • B3Lamp off everywhere. The unlit lamp in the rail title matches the unlit rows — the whole screen agrees about whose move it isn't.

C Filtered empty — the filter hides everything

The dangerous one: an empty screen that could be misread as "no work." It names the filter and offers the one-click exit back to reality.

  • C1Counts the hidden items. "5 items exist, none match" — the screen refuses to let a filter masquerade as an empty world. This is the truthfulness rule about missing evidence, applied to search.
  • C2Rail stays global. The rail is not filtered by the list's search — your move is your move regardless of what you're looking at. Filtering the rail would be lying by omission.
  • C3One click out. "Clear search" is adjacent to the claim, so the correction is always within reach.
